# Farmington & Question 2 (HB 1300) microsite

A one-page, plain-language voter guide explaining NH House Bill 1300 (Chapter 324, Laws of 2026), the school tax cap question on the November 3, 2026 ballot, and what it would mean for Farmington's schools. Every factual claim links to its source.

Built with [Astro](https://astro.build) as a static site. Deployed to Cloudflare Pages by GitHub Actions.

## Local development

```sh
nvm use          # Node 22 (see .nvmrc)
npm ci
npm run dev      # http://localhost:4321
npm test         # production build + outside-link check
```

## Editing content

| What | Where |
| --- | --- |
| Page copy and section order | `src/pages/index.astro` |
| Every source (title, publisher, URL, date) | `src/data/sources.ts` |
| Numbers used in charts and tables | `src/data/figures.ts` |
| Site title, "paid for by" line, last-updated date | `src/data/site.ts` |
| Styles | `src/styles/global.css` |

**Citing a source.** Add it once to `src/data/sources.ts`, then cite it next to the claim:

```astro
<Cite id="hb1300-chaptered" />                      <!-- uses the source's short label -->
<Cite id="hb1300-chaptered" label="RSA 32:5-i, VIII" />
<Cite id="school-board-video" href="https://www.youtube.com/watch?v=qcF6xnfGMWc&t=2160s" label="Watch at 36:00" />
```

`<Cite>` always renders `target="_blank" rel="nofollow noopener noreferrer"`, and the build fails if an unknown source id is used. `npm run check:links` also fails the build if any outside link anywhere on the page is missing `target="_blank"` or `rel="nofollow noopener"`.

The sources list at the bottom of the page is generated from the sources that are actually cited.

**Social share image.** `public/og.png` is generated by `node scripts/make-og-image.mjs` (needs Playwright + Chromium locally). Re-run it if you change the headline.

## Deployment (Cloudflare Pages via GitHub Actions)

The workflow in `.github/workflows/deploy.yml` builds and tests every push and pull request, then deploys:

- pushes to the production branch (`main` by default) → the live site
- pushes to any other branch, and pull requests from this repo → a Cloudflare preview URL (shown on the workflow run and in the PR's deployments)

### One-time setup

1. **Create a Cloudflare API token**: Cloudflare dashboard → My Profile → API Tokens → Create Token → *Custom token* with the permission **Account → Cloudflare Pages → Edit** (scoped to your account).
2. **Find your Account ID**: Cloudflare dashboard → Workers & Pages → the Account ID is shown in the right-hand sidebar.
3. **Add repository secrets** (GitHub → Settings → Secrets and variables → Actions → *Secrets*):
   - `CLOUDFLARE_API_TOKEN`
   - `CLOUDFLARE_ACCOUNT_ID`
4. **Optional repository variables** (same page → *Variables*):
   - `CF_PAGES_PROJECT` — Pages project name (default `farmington-hb1300`, which becomes `farmington-hb1300.pages.dev`)
   - `CF_PRODUCTION_BRANCH` — branch that publishes the live site (default `main`)
   - `SITE_URL` — final public URL, e.g. `https://www.example.org`, used for canonical and social-share links

The first deploy creates the Pages project automatically if it doesn't exist. Until the secrets are added, the deploy job is skipped with a notice and the build/test job still runs.

To use a custom domain, add it in Cloudflare → Workers & Pages → your project → Custom domains, then set `SITE_URL`.

- [ ] Fill in the "Paid for by" disclosure in `src/data/site.ts` (NH RSA 664:14 generally requires political advertising about a ballot measure to identify who paid for it — confirm what applies to you).
- [ ] Re-check items marked *needs confirmation* in `src/data/figures.ts` against the original downloads.
- [ ] Update `lastUpdated` in `src/data/site.ts`.
